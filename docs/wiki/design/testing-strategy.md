# Testing strategy

> The Rust crate is tested almost entirely with deterministic, hardware-free unit tests. These
> are about 1,130 runtime tests after macro expansion, kept beside the code in `#[cfg(test)]`
> modules. Around them sit 27 integration tests, 12 runnable doctests, and 9 `proptest`
> properties. Hardware behaviour is checked by hand, using the diagnostic examples. No Korg
> files are committed as fixtures. The single most important gap for a port to close is the
> SysEx receive path. Its fragmentation and realtime-byte filtering were fixed on hardware but
> have **no automated test**. The Zig port should cover it with a simulated device.

change the Zig port should make; see the Zig notes below. Layouts are defined on
[parameter encodings](../protocol/parameter-encodings.md).

### Mocks

[rust] `transport.rs` defines two test doubles. Both are public, not `#[cfg(test)]`, so
integration tests and users can use them.

| Double | Location | Behaviour |
|--------|----------|-----------|
| `MockOutput` | `transport.rs:48-81` | Implements `MidiOutput`; appends every `send(&[u8])` to a `Vec<Vec<u8>>`; exposes `messages()`, `last_message()`, `clear()` |
| `MockMidiInput` | `transport.rs:102-133` | Implements `MidiInput`; `queue_response(Vec<u8>)` pushes to a `VecDeque`. `receive(timeout)` pops the front, or returns `Ok(None)` **immediately** when empty. It ignores the timeout, so timeout tests take no wall time |
| `FailingOutput` | `sysex/transaction.rs:366-378` (`#[cfg(test)]`) | `send` always returns an error; proves error propagation |

### Hardware validation

There is no automated hardware test. Validation is manual and example-driven. [hw]

1. `sysex_roundtrip_diag` reads the edit buffer and decodes it. It then re-serializes the data
   and diffs all 1024 bytes, reporting the synth region (offsets < 156) and the sequencer
   region separately. It also compares the rebuilt SysEx message with the received one. Its
   `--compare A B` mode diffs two stored programs. This tool found the five byte-fidelity bugs
   fixed in commit `1c16566` ("byte-perfect"). See [byte fidelity](byte-fidelity.md) and
   [examples](examples.md).
2. `read_patch` and `read_edit_buffer` decode real programs. The test at
   `sysex/helpers.rs:155-161` uses a value from the factory program "Replicant xd": cutoff 665
   is stored as `99 02`.
3. Commit `bc6c452` found three things on hardware:
   - The device sends 24 ppqn clock (`F8`) before the SysEx reply.
   - Factory programs use user-param type value 3.
   - The SOUND-out / KBD/KNOB-in port pairing.
4. `AGENTS.md:31` and `CLAUDE.md:85-86` ask for byte-exact checks against real `.mnlgxd*`
   files and the gitignored `workbench/` Python references "when available". **No real Korg
   file is committed.** `sysex/program/file.rs` tests use synthetic `ProgramData` in memory.

## Invariants

Each of these is asserted somewhere in the Rust suite. Each should become a Zig test or
assertion.

- `decode(encode(x)) == x` for every byte string x. `encode(x).len == (n/7)*8 + (n%7 > 0 ? n%7 + 1 : 0)`
  where `n = x.len`. Every encoded byte is ≤ `0x7F`.
- `decode` rejects any input byte with bit 7 set, in any position of an 8-byte group.
- For every `v` in each encoding's domain, splitting into wire parts and rejoining gives `v`.
  Every value just outside the domain is rejected.
- The 10-bit receiver never yields more than 1023, whatever bytes it is fed.
- For every stepped parameter, every 7-bit RX value (0..127) maps to exactly one variant, and
  each variant's TX value maps back to that variant.
- `ProgramData` is exactly 1024 bytes. `SynthParams` (156) + `SequencerParams` (868) = 1024.
- Writing a 10-bit field leaves the upper 6 bits of its high byte unchanged.
- A NAK status ends a transaction with an error. A missing reply ends it with a timeout. An
  unexpected function ID ends it with `UnexpectedResponse`.
- An NRPN sequence interrupted by an unrelated CC produces no parameter.
- `ProgramNumber` accepts 0..=499 only; `bank = n / 100`, `slot = n % 100`.

## Errata & gotchas

- **Untested receive path.** `receive_sysex` (`sysex/transaction.rs:103-142`) does three things
  no test covers:
  - reassembles fragmented SysEx (commit `d465474`);
  - removes realtime bytes > `0xF7` embedded *inside* a SysEx chunk (`5e4b4f0`);
  - skips non-SysEx chunks before `F0` (`685ea64`).

  A grep for `0xF8`, `0xFE`, and `fragment` in the transaction tests finds nothing. These were
  hardware fixes [hw], so they are the highest-value tests to add in a port.
- **No byte-identity test.** Program round trips go struct → bytes → struct. Nothing feeds a
  real or randomized 1024-byte blob through bytes → struct → bytes and compares the bytes.
  Byte-identity was verified only on hardware with `sysex_roundtrip_diag` (`1c16566`).
- **CC count drift.** `KNOWN_CCS` lists 63 CCs (`tests/cc_coverage.rs:19-23`) and omits CC23
  (EG target). The receiver handles CC23 (`param/cc.rs:429`), and `device.rs:448-451` asserts
  64 named CCs. The integration test simply never checks CC23.
- **Weak assertions.** `ten_bit_cc_requires_cc63_preamble` only asserts `is_some()`
  (`tests/cc_coverage.rs:86-99`). The `sysex_flows.rs` tests check the *number* of messages
  sent, not their bytes (`tests/sysex_flows.rs:20-124`).
- **Ignored tests contradict the guidelines.** `device.rs:414-428` has two `#[ignore]` tests.
  `AGENTS.md:31` and `CLAUDE-CODE-COVERAGE.md:38,336` forbid ignored tests.
- **Fewer random cases than planned.** The plans ask for "1000 random" codec round trips
  (`docs/design/06-final/0001-minilogue-xd-rust-library-project-plan.md:83`,
  `docs/dev/0001-phase-1-implementation-plan-minilogue-xd-foundation.md:84`). The code runs
  proptest's default of 256, with an unrecorded seed.
- **Mock timeouts are instant.** `MockMidiInput` ignores the timeout. The deadline arithmetic
  in `receive_sysex` (`saturating_duration_since`, zero-remaining check) is never exercised with
  partial input followed by silence.
- **Golden file not tested.** `crates/minilogue-xd/examples/berlin_school.mid` (4,747 bytes)
  is committed, but no test regenerates and compares it. It was last regenerated in `4119473`.
  A later commit (`cdc0a73`) only moved `cc_name` out of `midi_file.rs`.
- **Coverage excludes integration tests** (`--lib`), and CI never measures it, so the 95 %
  target is self-reported.

## Rust design

- **Keep:** tests beside code, mocks as public types, table-driven tests generated by macro,
  and the habit of turning every hardware discovery into a regression test.
- **Keep:** the split between *clamping* builders and *rejecting* real-time setters. Both are
  tested: `tests/builder_roundtrip.rs:106-118` and `controller.rs` `f32_to_10bit_*`. See
  [builders](builders.md) and [realtime controller](realtime-controller.md).
- **Drop:** random-only property tests over small domains. Replace them with exhaustive loops.
- **Drop:** `#[ignore]` hardware tests. Model hardware with a simulator instead, and keep real
  hardware runs as acceptance demos.

## Zig / TigerStyle notes

**Runner.** Put `test "…" {}` blocks at the bottom of each source file, and cross-module and
fixture tests under `test/`, as on [module layout](../zig/module-layout.md). Run everything
with `zig build test`. Run CI on macOS, Linux, and Windows in Debug and ReleaseSafe. Assertions
stay on in ReleaseSafe, which matches the Rust debug/release split. The detailed plan is
[test plan](../zig/test-plan.md).

**Exhaustive tests for small domains.** All of these are cheap enough to run on every build.

| Domain | Size | Replaces |
|--------|-----:|----------|
| 7-bit data values | 128 | enum `rx_full_coverage` × 23 parameters |
| 10-bit values (CC split and NRPN split) | 1,024 each | `ten_bit_roundtrip`, `ten_bit_sysex_roundtrip` |
| 8-bit high-res values 0..=200, and rejection of 201..=255 | 256 | `eight_bit_*` |
| 14-bit values | 16,384 | `fourteen_bit_roundtrip` |
| Out-of-range `u16` values | 64,512 / 49,152 | `*_reject_out_of_range` |
| Receiver input pairs (`u8` × `u8`) | 65,536 | `receiver_always_valid` |
| Program numbers 0..=499 plus 500..=`u16` max | 65,536 | `program_number_addressing` |
| Codec: every single-byte value at every position 0..7 of a group | 2,048 | high-bit and known-value tests |

**Seeded property loops** replace `proptest` for the large domains: codec byte strings, blob
fuzzing, and the simulator. Use a fixed default seed, and allow an override from a build option
so a failure can be replayed. Bound every loop with a compile-time iteration count, and print
the seed and iteration on failure. Sketch (Zig 0.13-era std names):

```zig
// sketch
test "codec round trip, seeded" {
    var prng = std.Random.DefaultPrng.init(test_seed);
    const random = prng.random();
    var plain: [program_size]u8 = undefined;
    var wire: [codec.wire_size_max]u8 = undefined;
    var decoded: [program_size]u8 = undefined;
    for (0..codec_iterations_max) |_| {
        const plain_len = random.uintAtMost(u16, program_size);
        random.bytes(plain[0..plain_len]);
        const wire_len = codec.encode(plain[0..plain_len], &wire);
        const decoded_len = try codec.decode(wire[0..wire_len], &decoded);
        try std.testing.expectEqualSlices(u8, plain[0..plain_len], decoded[0..decoded_len]);
    }
}
```

**Negative space.** For every decoder, test invalid input as thoroughly as valid input:

- a high bit set in 7-bit data;
- truncated frames, a missing `F7`, and bytes after `F7`;
- a wrong manufacturer, family, or member ID;
- a wrong function ID;
- the unassigned status `0x25`, alongside the real NAKs `0x24` and `0x26`–`0x2F`
  (Korg MIDI Impl rev 1.01 NOTE 2);
- a bad `PROG`/`PRED`/`SQ` magic;
- program numbers ≥ 500;
- enum bytes one past the last variant.

The Rust tests do this for constructors and enums. The Zig port should extend it to every
parser. See [errors](errors.md) for the error sets.

**Fuzz-style decoders.** Feed seeded random byte streams to the stream parser, the SysEx
assembler, the frame parser, and `program.decode`. Assert that each returns either an error or
a value that re-encodes to bytes it accepts again. None may panic or overrun a buffer. All
buffers are fixed-size, so overruns show up as assertion failures. Zig's integrated fuzzer
(`zig build test --fuzz`, experimental) can drive the same entry points, but the seeded loop is
the portable baseline.

**Golden-byte vectors.** Commit the vectors listed above under `test/vectors/`. Also add
byte-exact program blobs captured from hardware: the edit buffer and at least one factory
program. Store them as raw 1024-byte files plus the received SysEx. Add the
`berlin_school.mid` output once export is ported. Each vector gets a bytes → struct → bytes
identity test, which the Rust suite lacks.

**Simulated device (mock XD).** Implement `test/simulation.zig` as a deterministic model of the
XD's SysEx side, driven by simulated time (the transaction takes `now_ns`; see
[SysEx transactions](sysex-transactions.md)). It needs:

- a 1024-byte edit buffer, a bounded set of stored programs, and a global blob;
- a reply to every request function ([SysEx framing](../protocol/sysex-framing.md));
- injected faults, chosen by a seeded PRNG under fixed bounds:
  - replies split into 1..N chunks at random boundaries;
  - `F8`/`FE` inserted between chunks *and inside* chunks;
  - non-SysEx messages before `F0`;
  - NAK instead of ACK;
  - a dropped reply (timeout), a wrong function ID, and a duplicate reply.

```zig
// sketch
const SimulationOptions = struct {
    seed: u64,
    reply_chunk_count_max: u8,
    realtime_insert_per_mille: u16,
    nak_per_mille: u16,
    reply_drop_per_mille: u16,
    noise_before_reply_bytes_max: u8,
};
```

Run each transaction a fixed number of times per seed, and assert the outcome from the
injected fault: success, `nak`, `timeout`, or `unexpected_response`. This replaces all 44
`transaction.rs` tests and the 8 `sysex_flows.rs` tests. It also covers the untested receive
path. Record outgoing bytes with a fixed-capacity mock output, as on
[TigerStyle mapping](../zig/tigerstyle-mapping.md), and assert the exact request bytes, not
just a message count.
